# 方案选择 · 航拍 OSD 参数提取

> 2026-11-22 ｜ 接《需求分析》。本文对比候选方案并给出选择结论与处理流程。

## 1. 总体路线：两条路

| | 路线 A：像素级 OCR | 路线 B：元数据解析 |
|---|---|---|
| 原理 | 参数"画"在画面里，抽帧识别像素中的文字 | 参数在 .SRT 字幕 / 飞控日志里，直接读文件 |
| 精度 | 取决于 OCR 与预处理 | 100% |
| 适用面 | 任何素材（图片/视频/录屏） | 仅带字幕文件的大疆类视频 |
| 算力 | 低（ROI 裁剪后毫秒级） | 近乎为零 |
| 题目契合度 | **高——题目就是"从画面提取"** | 低，绕过识别等于没做题 |

**结论：主路线 A**。路线 B 作为对比验证手段保留——若素材带 SRT 文件，用 B 的结果校验 A，现场演示"两路一致"是加分项。

## 2. 环节选型

| 环节 | 主选 | 备选 | 理由 |
|---|---|---|---|
| 抽帧 / 预处理 | OpenCV | — | VideoCapture 循环抽帧；ROI 放大 2~3 倍 + 自适应二值化 |
| OCR | PaddleOCR（PP-OCRv4） | RapidOCR（onnxruntime 版） | 中英+数字小字识别现役开源最强，CPU 裁剪 ROI 后几十毫秒；Tesseract 对屏幕叠字弱，不选 |
| 数值解析 | 正则 + 单位换算 | — | 兼容度分秒/十进制两套经纬度、ft↔m、° 符号、OCR 常见错字容错 |
| 输出 | 终端打印 + 画面叠加（半透明数值条） | tkinter 面板 | 本阶段文本输出即可，叠加显示保证演示对照 |
| 语言 | Python 全家桶 | — | 用户主力语言，生态全 |

不做语音播报（本阶段需求明确）。

## 3. 处理流程

```
图片/视频 → ①抽帧(2~5 FPS) → ②ROI裁剪(一次标定) → ③预处理(放大+灰度+自适应二值化)
→ ④OCR → ⑤正则解析(归类+归一化) → ⑥去抖(连续3次一致) → ⑦文本输出(终端+画面叠加)
```

各环节要点：

1. **抽帧**：不需要每帧都 OCR。参数不是帧级变化的，2~5 FPS 采样足够，算力省一个量级
2. **ROI 裁剪**：OSD 位置固定，首次标定一次，之后只处理那一小块。面积缩小 30 倍以上——速度与准确率双赢（同时排除画面里其他文字的干扰），是方案能实时成立的核心
3. **预处理**：放大把字送进模型舒适区；灰度丢三通道；**自适应阈值**二值化按局部邻域亮度定阈值——OSD 白字黑边压在明暗不一的背景上，切完只剩干净黑底白字
4. **OCR**：PaddleOCR，识别裁剪后的小块文字
5. **解析**：正则按关键词（H/HDG/ALT/航向/高度）与格式特征（数字+°、数字+m）双保险归类；经纬度两格式统一转十进制度，高度统一转米；允许 OCR 错字（0/O、° 丢失）
6. **去抖**：连续 3 次读到相同值才更新，防 OSD 闪烁跳变（3 次 × 0.5 s = 最坏 1.5 s 确认延迟，可接受）
7. **输出**：终端实时打印；结果画回画面右下角，面试官肉眼对照"画面值 = 读出值"

## 4. 性能预算

- 1080p 全图 OCR：约 200~500 ms（CPU）
- ROI 裁剪后：30~80 ms
- 2 FPS 采样 → CPU 占用 10~20%，延迟最坏 0.5 s——满足"实时"指标（N1）

## 5. 实施里程碑

- **M1 环境 + 侦察（半天）**：装 opencv-python / paddleocr；素材到手先 OCR 一帧，回答三个问题——字多大（定放大倍数）、格式长什么样（定正则）、识别率多少（定预处理后手）
- **M2 图片版跑通（1 天）**：单帧 → ROI → 预处理 → OCR → 解析 → 打印 + 叠加
- **M3 视频实时版（1 天）**：抽帧循环、去抖、画面叠加、终端持续输出
- **M4 演示包装（半天）**：演示脚本 + 合成测试素材 + 讲稿

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 小字识别差 | ROI 放大 3 倍 + 锐化 |
| 复杂背景干扰 | 自适应二值化（白字黑边切后只剩字） |
| OSD 闪烁 / 跳变 | 连续多数投票去抖 |
| 经纬度格式不统一 | 两套正则 + 单位换算函数 |
| 素材缺失 | 用 PIL 生成合成测试素材（航拍背景 + 白字黑边 OSD，数值已知），先验证链路，演示现场也能用 |

## 7. 演示讲法

一句话主线：**"OSD 参数是像素级的文字，我走 ROI 裁剪 → 预处理 → OCR → 正则解析 → 去抖输出的流水线；视频若带大疆 SRT 文件，还能走元数据直读做交叉验证。"**

开场 10 秒讲架构，再放 30 s 素材演示。埋两个技术钩子等面试官问：为什么只认 ROI（算力账）、为什么去抖（OSD 闪烁）。
